# Pre-registration draft, 2026-11-07: 48.15, masked-column objective

**DRAFT, 2026-11-07, before any arm trains.** Not yet in FINDINGS.md; meant to be merged there
as its own pre-registration before the kernel is pushed. Task: `openspec/changes/learn-from-peers`
48.15, whose Verify scopes it as a measurement before a rewrite. Nothing here has trained or
been scored; every cost is ESTIMATED unless marked MEASURED. Recipe, control, rule and checks
follow `preregs_2026-11.md` (its "Common to every arm"), which this file does not repeat beyond
what the arm changes.

## What was built

- **Flag.** `fintfm-train --masked-column-prob P` (config key `train.masked_column_prob`),
  default 0.0. At 0.0 the code never touches a batch: the task sequence, the weights and the
  provenance are those of every earlier checkpoint (`tests/test_masked_column.py`). Nothing in
  the inference API, the model, the head or the loss changes.
- **Mechanism.** After a step's batch is drawn (by either loader), each task is replaced with
  probability P by a task from the same table in which one feature column is the target
  (`src/fintfm/modeling/masked_column.py`). It is a **replacement, not an addition**: tasks seen
  stay 48,000, so the arm is matched to its control in tasks, steps and seed.
- **The swapped task.** A feature column observed in every row is chosen at random. It is
  **binarised** at a quantile of its context rows (target rate drawn from 0.1 to 0.5, direction
  of the cut random) and becomes the label. The original label is written into that column's
  slot as a feature, so width and every other column are unchanged. A column that is constant
  in the context, or whose cut leaves fewer than 2 context rows in a class, is passed over for
  the next candidate; a task with no valid column keeps its original target. Padded columns
  (all NaN) and partly missing columns are never chosen, since a missing cell has no target.
- **Why binary, not quantile bins into 2 to `max_classes` classes.** The published recipe's head
  is binary (`max_classes` 2) and V4FinBench is a binary, low-default question; the loss and the
  inference-time base-rate correction both read the label as "the rare class". A multi-class
  bin target would ask the head a different kind of question and change what it learns for
  reasons that are not the masked objective. At `max_classes` 2 it would not fit the head
  anyway. The cost of the choice is stated under limitations.
- **No leakage.** The cut is computed from context rows only (tested: changing query rows
  leaves every context-side target unchanged), so a swapped task has no query information the
  original did not.
- **RNG.** Swap draws use `default_rng([seed, 3, rank, step, 1])`, rebuilt each step, never the
  prior's generator and not a stored state. So the underlying task sequence is identical with
  the flag on or off (tested), a resumed run swaps what an uninterrupted one would, and no
  checkpoint format changes. The trailing non-zero word keeps the key distinct from the stream
  loader's `[seed, i]` and the evaluation keys.
- **Held-out monitoring.** The in-training held-out evaluation scores untouched target-only
  tasks, as in the control.

### Why P = 0.25

A one-dose measurement has to be large enough to show an effect and small enough not to
confound it with simply losing target-only tasks. At 0.25 the arm trains on about 12,000 masked
tasks and about 36,000 target-only tasks, three quarters of the control's target-only signal.
At 0.5 a harm could come from halving the target-only volume as much as from the masked
objective itself. At 0.1 the arm sees about 4,800 masked tasks, too few for a null to say much.
This is a judgement, not a measurement; a second dose is earned only through §175's rule.

## Adoption rule (§175's, unchanged; AP first)

Primary measure: five-fold zero-shot V4FinBench mean AP, full panel, packaged inference
defaults, scored by the kernel template; paired company-level bootstrap per fold, Holm across
the five folds (`uv run python scripts/compare_v4_scores.py --cluster --control
runs/kaggle-ts-e1-v48-s0/e1-v48-s0/score 4815-maskcol-s0=runs/kaggle-ts-4815-maskcol-s0/4815-maskcol-s0/score`).

| verdict | condition |
| --- | --- |
| **promising** | mean AP above the control's by more than **0.0117** (§173), with at least 4 of 5 folds positive |
| **harmful** | the mirror: below by more than 0.0117, with at least 4 of 5 folds negative |
| **null** | anything else |

Report the five per-fold AP differences and their **Holm-corrected fold p-values** beside the
verdict, then ROC-AUC (second, never alone), then the difference against `e1-v48-s1`. One seed
screens; it adopts nothing. Promising: a seed-1 replicate, then the rewrite question 48.15 left
open (a joint-objective model with conditional queries). Null or harmful: the objective is not
carried forward at this model size on this evidence, and 48.15 closes with the result.

## Failure mode named in advance

**Masked modelling spends capacity reconstructing features nobody will query, and at 885,650
parameters that trade may be strictly bad.** LimiX-2 is 16M parameters; its 2M variant is the
relevant comparison, not its headline, and this model is smaller still. A **harmful** verdict is
a live outcome, at least as likely as a gain. The arm cannot tell "the objective is bad" from
"the objective is bad at 885K parameters"; only the second is measured.

## Limitations, stated before the result

- **Binary target, not the LimiX-2 objective.** LimiX-2 masks cells and reconstructs them
  context-conditionally; this arm reconstructs one thresholded column, a narrow,
  classification-shaped proxy of the joint objective. A null here does not refute the joint
  objective at larger scale.
- **Coarse reconstruction.** A binary cut keeps about one bit of the column, so the swapped
  tasks teach dependence between columns, not their values.
- **Column selection favours fully observed columns**, which under MCAR missingness excludes
  the columns with the most missing cells.
- **Target base rate.** Cuts aim at a 0.1 to 0.5 context rate, higher than the 0.001 to 0.30
  band the financial prior draws for labels, so swapped tasks are on average less imbalanced
  than target-only ones.
- **Orientation is randomised** (cut direction random), so no fixed feature-to-label rule can
  be memorised across swapped tasks (the §47 failure). A label written in as a feature is a 0/1
  or class index, a scale the original columns do not have.
- **No survival or quantile heads.** The flag refuses a quantile head and a batch carrying
  default periods.

## Cost (ESTIMATED)

- **Basis.** Whole 48,000-task train-and-score sessions on Kaggle T4x2 from the kernel logs:
  1.50 to 1.91 h (`e1-v48-s0` 5,403 s, `dr24-a-s0` 6,686 s, `dr62-induced-s0` 6,891 s, MEASURED,
  `preregs_2026-11.md`); the control trains at 0.525 s per step. The swap is host-side NumPy
  once per step: **0.8 ms per call at P = 0.25 and 16.8 ms at P = 1.0** on a 4 x 1,024 x 136
  batch (SMOKE-TEST on this Mac, 20 calls, one core), against 525 ms per step. The model sees
  the same shapes, so GPU memory and step time are the control's.
- **Estimate: 1.5 to 2.0 GPU-hours for the arm** (one session, train then score), the same as
  the other control-cost arms. A seed-1 replicate, if earned, costs the same. Kaggle's
  per-hour charging is not checked against its documentation.
- **Checks during the run.** The step-1,000 line of `train.log` against the control's 525 s;
  the `masked-column swaps` count in each log line should grow by about 1 task per step per
  rank (0.25 x 4 tasks), nearly all eligible. A count near zero means the eligibility filter is
  skipping nearly every task (heavy missingness) and the arm is not testing what it says.

## Checked so far (SMOKE-TEST, 2026-11-07)

`tests/test_masked_column.py`: the default reproduces the same batch sequence and weights; the
underlying task sequence is unchanged with the flag on; P = 1 swaps every eligible task with
valid shapes and dtypes; the target is a cut of a removed column and the original label sits in
its slot; bin edges ignore query rows; constant, missing and padded columns are skipped; a
4-step CPU training at P = 0.5 completes; the kernel differs from au53's by the lever alone and
carries the placeholder commit. This proves the pipeline runs and says nothing about quality.
