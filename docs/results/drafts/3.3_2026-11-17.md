## Result (gaps first)
- On V4FinBench the time-based split does not show random-split optimism. Six of seven models score higher average precision (AP) on the time window than on the random window; only fintfm is flat (AP 0.0754 random, 0.0698 time). The Verify's expectation that the random split flatters the models is not supported here.
- The two windows have different test base rates (time 0.988%, 390/39,478; random 1.467%, 579/39,478), and AP scales with base rate, so an AP difference between windows is not a like-for-like gap. AUC is base-rate independent and also rises on the time window for all seven models (+0.028 to +0.050).
- fintfm is last on AP in both windows (random 0.0754, time 0.0698) against 0.17-0.26 (random) and 0.18-0.31 (time) for the six baselines. On the time window it predicts a mean 2.684% against an observed 0.988% and its Brier skill is -5.80% (worse than a constant at the base rate).
- The Verify's literal command (`fintfm-bench --credit`) did not finish: the credit unit timed out at 18,000 s inside the fintfm time arm. The table below is assembled from two units that print identical random-window numbers (see Integrity).
- The UCI credit panels have no period column, so they carry random-split numbers only ("time-based split: NOT AVAILABLE" printed per panel).

## Caveats
- One seed, one train/test cut (train <= 2016, test >= 2017), one checkpoint, 100,000 of 1,000,087 rows. No fold or seed spread, so no interval can be placed on any gap. The Brier and AP differences between models in Table 1 are single-run numbers.
- AP gaps mix the split effect with a base-rate change (1.467% vs 0.988%). A like-for-like comparison would need a random window matched to the time window's base rate, or AP lift over base rate. Not done here.
- 9,605 companies are in both windows; the harness dropped 13,337 train rows for it (default behaviour), so train sets are not the same size across the two windows if the random window did not apply the drop; this draft did not check whether it did.
- Time ordering helps the baselines here: the train window carries a higher base rate (1.867%) than the test window. That is a property of this panel, not a general property of time splits.
- ts200k (scaling check) was not run, so how the gap moves with panel size is unmeasured; the tasks.md estimate of 50,000 rows first (`h-timesplit50k`) is a separate local run not covered here.
- The UCI panels cannot be time-split (no dates), so the Verify's phrase "prints both" holds for V4FinBench only.
